## Benchmark Overview

- **Math** rows verify mathematical statements or proofs. **Software**, **Hardware**, **Contract**, and **Protocol** rows verify engineered artifacts.
- Dates link to the first public paper/resource when available; the second field is included only for an accepted or published venue.
- **Citations** are OpenAlex `cited_by_count` values for the linked benchmark/method paper, retrieved on 2026-09-20. For title-equivalent preprint/proceedings records, the highest-count record is used; ties preserve the prior order, and unindexed resources appear last.
- Method papers with a named, reproducible evaluation set are marked **Eval**. Unverified resources such as Ineq-Comp and proposal-only artifacts such as SWE-Proof are not listed as confirmed benchmarks.
- The second column records **upstream source -> construction/filtering -> final task unit**. If a paper does not enumerate exact upstream items, this is stated explicitly.
- **Repository context**, a **whole-repository deliverable**, and the **upstream repository's primary purpose** are separate properties. A theorem or VC may use project context without asking the model to verify the repository as a whole.
- **General-software upstream** means that the repository's main product is a software system or library; it may still contain substantial formal verification. **Formal-purpose upstream** means that its main product is formal Specs, proofs, verification libraries, or verification tooling. Whether formal artifacts already existed before benchmark curation is recorded separately.
- In the last column, every line follows: **Metric**: `Input -> Output`; **Verify**: evaluation oracle.
